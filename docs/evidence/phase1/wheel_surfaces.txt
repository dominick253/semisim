CITYHAUL AS4e: surface-dependent tire mu, saturation and ABS become reachable
=============================================================================

Repo state: on main at HEAD 353d539 (after AS4d). This slice changes only
scripts/vehicles/wheel_rig.gd, scripts/vehicles/combination_controller.gd
(suspension step), tests/unit/test_wheel_surfaces.gd (new),
tests/scratch/wheel_saturation_probe.gd (surface argument), this file, and one
row (D49) in docs/DEVIATIONS.md. No PHYSICS_CONSTANTS value, the tire model,
the friction ellipse, the ABS thresholds or the AS4d no-slip assignment were
touched.

## The change

WheelRig.mu() returned tire["mu_dry"] unconditionally, so the mu_wet 0.72 and
mu_ice 0.25 columns of the tire table were dead data and the friction ellipse
never saturated: 21,314 N demand against a 65,654 N adhesion limit on the dry
yard, abs_engaged false, slip never leaving about -0.003
(docs/evidence/phase1/wheel_roll.txt).

Now:

1. WheelRig gains var surface: String = "dry" and var ground_rid: RID.
   mu() returns tire["mu_" + surface], falling back to tire["mu_dry"] when the
   key is missing, with a one-time push_warning per unknown name (not every
   tick). It never crashes on an unknown name.
2. In the combination controller's suspension step the hit collider's RID is
   stored per wheel, and only when it changes does the controller read
   w.surface = String(collider.get_meta("surface", "dry")). Rationale in the
   code: String(...) from a Variant allocates, and the wheel step runs eight
   times per tick at 120 Hz, so the meta read is gated on a RID change instead
   of running every tick. On a ray miss the stored RID resets, so the next
   contact re-reads. No meta means "dry", so the untagged yard keeps
   byte-identical behaviour.
3. D49 (docs/DEVIATIONS.md): the surface channel is a collider meta tag rather
   than a physics material, because the raycast suspension (D21) has no contact
   object to read a PhysicsMaterial from and the torque-demand tire model takes
   fz and mu as plain numbers per wheel step.

## Measurement pitfall found and fixed along the way

The first ice probe run was contaminated. A SceneTree-script probe that swaps
the ground in _init finds no old ground, because the harness builds its ground
in _ready, which in SceneTree-script mode runs on the first frame, not during
_init. The swap therefore left a SECOND co-located ground, and the suspension
ray tie-flipped between the two identical-height surfaces every frame: the
surface (and hence mu) flickered ice/dry, and the first ice SAT block showed
dry-mu adhesion (66,675 N) at t=4/5. Measured with a temporary tracer probe
(removed), which showed the hit RID alternating between the two StaticBody3D
colliders every frame. The probe now defers the swap to the first _process
tick, after the harness _ready has run; the corrected ice run above shows a
constant ice adhesion. The unit test is unaffected: under GUT the harness
_ready runs synchronously during add_child, so its swap finds the old ground.
